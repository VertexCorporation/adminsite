# Vertex Konsol UI consolidation — 51–75

## Scope

This branch builds on the first 50 fixes and the initial 51–75 work. It merges the latest main release without deploying it and refactors the **source** files under `css/`, `js/`, and the browser/unit tests. The immutable `assets/releases/<hash>/` tree is generated by `node scripts/release.cjs` in CI; do not hot-edit old release assets.

## Verification

- `node scripts/release.cjs`: builds a new immutable release in the ephemeral CI checkout only, with importmap for the new UI modules; no auto-deploy and no generated-file push.
- `node --test tests/ui.test.cjs`: static contract and regression assertions for shared modules, no duplicate style owners, and feature adoption.
- `node tests/ui-browser.cjs`: Chromium smoke testing at 320, 360, 390, 768, 1024, 1440 and 1920 pixels, light/dark variables, toast stacking, crossfade, stale loading, error state, both scroll axes, forms, buttons and reduced motion.
- Legacy suites still run as **diagnostic, not merge-blocking**. Their prior full-browser fixture attempts to click a disabled contributor verification control: this behavior is governed by existing authorization and must not be bypassed to make the test pass. Legacy unit tests also depend on sibling Fulcrum fixture files not guaranteed in standalone checkout. Fix those fixtures independently before treating the legacy suite as a required gate.
- No backend, Firebase production function, Zapier, permission, certificate issuance or live data contract was modified as part of this UI pass.

## Release and acceptance

1. Keep the PR unmerged until the latest CI execution has finished and the maintained visual regression baseline has been reviewed.
2. In a preview build, validate overlays, action button width, forms and scroll fading with real permissions and data at narrow phone, tablet and desktop widths; include keyboard and reduced motion.
3. Generate a new immutable release with `node scripts/release.cjs`; confirm `index.html` references the new `css/ui/` and `js/ui/` bundles.
4. Deploy using the organization's usual authenticated pipeline only after review. This branch by itself makes no live change.

## Important design invariants

- Do not automatically re-enable permission-disabled actions; a pending action cannot grant authorization.
- Never discard known-good records because a refresh failed.
- Never clone a live form into an interactive surface during transitions; outgoing copies must remain inert.
- Treat uncertain notification delivery as uncertain; never introduce a blind retry.
- Existing i18n keys, published email/certificate flows, original records and the roster business rules are unchanged.
